# Аналитика: единое оформление и достоверность

Маршрут `/analytics` использует HomeShell с активным пунктом аналитики. Общая палитра мигрированных разделов переиспользована без изменения значений: Sidebar #0A1427, белые/тёмные поверхности, красные основные действия. Новый `analytics.css` ограничен `.workspace-analytics`. Компоненты и CSS Dashboard не изменены. `charts.tsx` используется только аналитикой, Dashboard использует отдельные графики.

Сверху четыре KPI: всего; активные (NEW + UNDER_REVIEW + NEEDS_CLARIFICATION + IN_PROGRESS); просроченные из API; завершённые из API. Далее широкий график динамики и компактная диаграмма типов, топ категорий и таблица подразделений. Дополнительные показатели: реализованные предложения, доля завершённых в срок, среднее время первой реакции с размером выборки. Градиенты графиков убраны, серии переключаются прежними кнопками. Длинная таблица прокручивается горизонтально, страница — естественно по вертикали. На узких экранах сетки перестраиваются, график сохраняет читаемый размер с горизонтальной прокруткой.

Периоды 7/30/90/all и API `analytics/overview` сохранены. UI объясняет, что обращения фильтруются по дате создания, архив учитывается, а график событий ограничен этой выборкой. Точки обозначены интервалами, не календарными днями. «Первая реакция» означает первую смену статуса либо первый публичный комментарий обработчика; текстовый ответ не обязателен. Подпись «Рассмотрено» удалена. Не добавлялись исторические сравнения или оценки эффективности.

Доля завершения в срок берётся из `onTimeShare`; знаменатель — завершённые обращения выборки с датой закрытия. Отмечены сравнение с сохранённым сроком и отсутствие отдельного размера этого знаменателя в API. При null показывается «Нет данных». Средняя реакция показывается только при наличии выборки; пустые распределения не получают фиктивные проценты.

Область видимости показывается по `scope` ответа сервера. CSV содержит только `byDepartment` из того же ответа, область и выбранный период. При загрузке/ошибке/пустой выборке экспорт отключён. Ссылок на недоступные карточки и дополнительных запросов расширенной статистики нет. `analyticsScope`, `ticketScope`, авторизация и дополнительное право `canViewCompanyAnalytics` не изменены.

В `useResource` добавлено только поле `loadedAt`: фиксируется при успешном получении ответа, сохраняется при ошибке того же запроса, не переносится на другой URL/период. В UI и CSV это время получения данных браузером, не время изменения БД. Другие экраны это поле не используют.

Изменены: `analytics-screen.tsx`, `charts.tsx`, `use-resource.ts`, подключение маршрута в `app-frame.tsx`, класс в `home-shell.tsx`, область общих токенов в `tickets.css`, импорт CSS в `layout.tsx`, проверки оболочки и существования дизайн-токенов. Добавлены `analytics.css`, `analytics-ui.test.tsx`, `resource-timestamp.test.tsx`.

Проверки: typecheck, lint, 381 тест и build прошли. DOM-тесты проверяют обе темы, KPI, все периоды, CSV и область, пустые/ошибочные/загружаемые данные, повтор запросов и переключение серий. Серверные функции областей доступа проверены для EMPLOYEE/MANAGER/ADMIN и дополнительного права; тест подтверждает, что это право не расширяет `ticketScope`. Отдельный тест проверяет реальное поведение hook `useResource` со временем получения ответа. UI API в тестах подменён; запросы записи и изменения реальных данных не выполнялись.

Все существующие проверки Dashboard, реестра, создания и карточки также прошли. По diff компоненты Dashboard, его CSS, backend, API, авторизация, PostgreSQL и миграции не изменены. Это проверка кода и регрессий, не визуальное утверждение.

HTTP: `/`, `/tickets`, `/tickets/new`, `/analytics` — 200; `/api/v1/health` — 200, database connected. Браузерный сервис недоступен (`The browser access host is unavailable`), поэтому скриншот и реальная визуальная проверка обеих тем/размеров окна остаются открытыми. Build содержит прежнее предупреждение о внешнем lock-файле в D:\Projects, но завершается успешно. Push и deployment не выполнялись.
