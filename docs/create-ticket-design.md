# Создать обращение: оформление и проверка

Маршрут `/tickets/new` использует существующий HomeShell и активный пункт «Создать обращение». Его палитра переиспользует общие токены Dashboard через блок мигрированных разделов в `tickets.css`. Новый `create-ticket.css` ограничен `.workspace-create`: белая карточка в светлой теме, тёмная поверхность в тёмной, красные действия, Sidebar #0A1427, скругления, компактные поля. CSS и компоненты Dashboard не изменены; правила реестра остаются в его области действия.

Порядок полей сохранён. Подсказки показывают обязательность, границы длины и лимиты файлов. На мобильных устройствах варианты выбора и кнопки становятся вертикальными, текст полей — 16 px, подсказки — 12 px. Высота страницы не ограничена, textarea можно увеличивать, прокрутка естественная.

Клиентская валидация выполняется перед отправкой с обрезкой крайних пробелов: тема 3–200, описание 10–10 000 символов, действующая категория обязательна. `noValidate` позволяет показывать единые сообщения возле полей; `required`, `minLength` и `maxLength` сохранены. Ошибки API с известными путями сопоставляются полям, используются `aria-invalid`, `aria-describedby`, `role=alert` и фокус первого ошибочного поля. Ошибки не очищают введённый текст.

Добавлены повтор получения категорий и отдельное состояние пустого списка. Кнопка повторной загрузки в общем ErrorNotice имеет `type=button`, чтобы внутри формы не запускать отправку. Синхронная блокировка через ref предотвращает два обработчика отправки до обновления React-состояния.

Создание и загрузки используют прежние API. После создания номер/ID обращения сохраняется; уже загруженные файлы удаляются из очереди, повтор отправляет оставшиеся с обновлённой версией обращения. Модуль FilePicker и серверная логика вложений не изменены. Есть выбор файлов, drag-and-drop, удаление из списка и прежние ограничения форматов/размера/количества.

Проверки: typecheck, lint, 295 тестов и build. Новые DOM-тесты выполняются в обеих темах и покрывают длины на границах и за ними, обязательность категории, тип/приоритет, передачу данных, ошибки категорий/API/сети, сохранение текста, повторную отправку, последовательную загрузку вложений без повторного создания, ограничения файлов и доступность элементов фокусу. Ответы API в этих тестах подменены; реальное новое обращение при проверке не создавалось.

HTTP: `/`, `/tickets`, `/tickets/new` возвращают 200; `/api/v1/health` возвращает 200 и `database: connected`. Браузерный сервис вернул `The browser access host is unavailable`: скриншот, реальная клавиатурная навигация, геометрия на разных окнах и визуальное утверждение остаются для проверки в браузере.

Сборка предупреждает о внешнем lock-файле в `D:\Projects`, но завершается успешно. Backend, API, авторизация, PostgreSQL и миграции не изменялись. Push и deployment не выполнялись.
