# Карточка обращения: единое оформление

Маршруты `/tickets/[id]` подключены к существующему HomeShell. В меню активен раздел обращений; Sidebar и Header не дублируются. Отдельный класс `.workspace-detail` использует общие токены мигрированных разделов. Новые стили ограничены карточкой: Sidebar #0A1427, белые/тёмные поверхности по теме, красные основные кнопки, нейтральные вторичные, скруглённые карточки и диалоги. Стили Dashboard, реестра и формы создания не переработаны.

Сохранены две колонки: основное содержимое и обсуждение слева, действия, исполнитель, подразделение, приоритет, срок и решение справа. При ширине до 1200 px — одна колонка; на мобильных этапы становятся сеткой 2×2. Содержимое не скрывается по высоте, длинные тексты и имена файлов переносятся. Подписи и даты имеют размер от 12 px.

Комментарии, история и вложения имеют независимые состояния загрузки, ошибки с безопасным повтором GET и пустого списка. Пустые сообщения не показываются при ошибке или загрузке. Вкладки поддерживают стрелки влево/вправо с циклическим переходом, Home/End, один tab stop и фокус активной вкладки. Переход из краткой истории фокусирует вкладку истории.

API истории не менялся. Краткая история явно подписана как фрагмент текущей страницы с её номером и общим числом страниц. Вкладка истории показывает пагинацию и количество доступных событий. Даты промежуточных этапов берутся только из загруженных событий, это ограничение объяснено рядом; отсутствие даты не выдаётся за отсутствие события во всей истории.

Сохранены существующие API действий, ограничения ролей и запрет обработки своего обращения. Серверные проверки не изменены. Комментарии и решение сохраняют введённый текст при ошибке. Повторные параллельные отправки блокируются. Диалог назначения не разрешает сохранение при ошибке получения пользователей и предлагает повтор загрузки. После конфликта версии загрузка вложений использует более свежую версию карточки, сохраняя оставшиеся файлы.

Изменены на этом этапе: `app-frame.tsx`, `home-shell.tsx`, `ticket-detail.tsx`, `ticket-action-dialog.tsx`, подключение CSS в `layout.tsx`, область общих токенов в `tickets.css`, тест маршрутов оболочки `auth-ui.test.tsx`. Добавлены `ticket-detail.css` и `ticket-detail-ui.test.tsx`.

Финальные проверки: typecheck, lint, 350 тестов и build прошли. Новые DOM-тесты покрывают обе темы, EMPLOYEE/MANAGER/ADMIN, собственные обращения, назначенного руководителя другого подразделения, состояния ресурсов, вкладки, пагинацию, комментарии/служебные заметки, запрос уточнения, редактирование, назначение, срок, решение, восстановление из архива, ссылки вложений и повтор загрузки после конфликта версии. Часть тестов вызывает неизменённые серверные функции `canManage` и `ticketScope`. Запросы записи API в UI-тестах подменены, реальные обращения и файлы не изменялись.

HTTP-проверки локального сервера: `/`, `/tickets`, `/tickets/new` и HTML-маршрут карточки возвращают 200. Для проверки HTML карточки использован фиктивный UUID; это не подтверждает загрузку реального обращения. `/api/v1/health` возвращает 200 и `database: connected`.

Браузерный сервис недоступен (`The browser access host is unavailable`). Скриншот, визуальная геометрия обеих тем/размеров окна и реальная клавиатурная проверка модальных окон не подтверждены. Сборка завершилась с прежним предупреждением о внешнем lock-файле в `D:\Projects`. Backend, API, авторизация, PostgreSQL и миграции не менялись; push и deployment не выполнялись.
