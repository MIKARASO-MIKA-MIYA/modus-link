## Что проверено интеграционно

Исходные тексты, категории и условные авторы/исполнители A-001—A-020; отсутствие дублей после повторного seed; реальные сессии и logout; обязательные поля и запрет клиентского назначения роли; Origin; маршрутизация с приоритетом подразделения над глобальным правилом; глобальный fallback; сохранение без правила и нераспределённая очередь; недоступность чужих деталей, комментариев, истории и операций; ручное назначение; запрет самоутверждения; сохранение истории и блокировка устаревших версий; фильтры и пагинация; внутренние комментарии и первый ответ; уточнение и ответ автора; отказ с обязательной причиной; результат при CLOSED; архив и чтение результата автором; запрет DELETE и изменения истории в PostgreSQL; конкурирующие изменения с откатом проигравшей истории; IN_PROGRESS → IMPLEMENTED; запрет результата null и outcome null на уровне БД; DB-ограничитель входа; области аналитики и отдельное право собственника; отключение правила после деактивации категории; административное изменение роли и отзыв старых сессий.

Модульные тесты дополнительно проверяют точные формулы метрик, среднее по timestamps, сохранение исхода при CLOSED, пустую сводку, календарные сроки, матрицу полномочий, переходы, границы валидации и хеширование паролей.

## Основная демонстрационная база после проверок

В modus_pulse осталось ровно 20 обращений, все исходные синтетические. Интеграционные обращения создавались только в modus_pulse_test. Smoke-проверка изменяла только сессии и счётчики входа, затем выполняла logout.

| Аккаунт | Карточек в реестре | Обращений в аналитике |
| --- | --- | --- |
| employee@modus.local | 4 | 4, OWN |
| manager@modus.local | 4 | 4, DEPARTMENT_AND_ASSIGNED |
| admin@modus.local | 20 | 20, COMPANY |
| owner@modus.local | 0 | 20, COMPANY |

У собственника нет собственных/назначенных карточек в seed; общая аналитика доступна независимо. Это намеренное разделение прав, описанное в architecture.md.

Интерфейс по присланным макетам доступен на http://localhost:3000; PostgreSQL и Next dev оставлены работающими в текущей сессии. После завершения процессов запустите db:local и dev согласно README. Нагрузочные испытания и промышленный периметр этой проверкой не охватывались.
## Проверка после подключения дизайна

Реализованы кабинеты, реестр, форма создания, карточка, настройки, профиль, уведомления и SVG-аналитика по макетам. Всего 43 автоматизированных теста: 17 unit + 26 integration. Добавлены проверки разрешённых и запрещённых файлов, размера и MIME, закрытого скачивания, IDOR вложений, отката на устаревшей версии, истории ATTACHMENT_ADDED, фильтра ответственного/автора, поиска автора, сортировки, групп статусов, архива, периодов и реальных временных серий аналитики, публичных уведомлений.

Основной реестр не изменялся: пользовательские тесты выполнялись только в modus_pulse_test. Файлы тестов отделены от основного хранилища. Скрипт smoke проверяет HTTP-доступность всех страниц и реальные вход/выборки четырёх ролей; он не имитирует клики и не считается браузерной проверкой.

Визуальная проверка попыталась открыть локальную страницу через Computer Use. Browser access host оказался недоступен; затем Windows-управление Chrome было остановлено инструментом, поскольку он не смог уверенно определить URL для проверки политики. После остановки UI-ввод не выполнялся. Поэтому отрисовка на desktop/mobile и попиксельная сверка с макетами не подтверждены браузерным прогоном. Адаптивные стили реализованы, код компилируется; точные результаты HTTP-smoke и сборки фиксируются командами, а не предположением об отрисовке.

Финальный прогон после подключения дизайна: TypeScript и ESLint завершились без ошибок; production build завершился без предупреждений; npm.cmd test — 17/17; npm.cmd run test:integration — 26/26. npm.cmd run smoke подтвердил HTTP 200 всех 12 экранов, подключение БД и четыре сессии. В основной БД по-прежнему 20 исходных синтетических обращений.

## Вход по нику и своему паролю — 11 ноября 2026

Регистрация сотрудника использует username/password без email, после создания выдаётся серверная сессия. Проверен полный сценарий на настоящем Next.js API и PostgreSQL в отдельной `modus_pulse_test`: придуманный русский ник с заглавными буквами нормализуется, создаётся аккаунт без почты, сохраняется обращение, после logout прежняя cookie отзывается, повторный вход тем же паролем возвращает тот же id и доступ к обращению. Неверный пароль отклоняется.

Проверены коллизии ников при одновременной регистрации и после нормализации, отсутствие хеша пароля в ответах, запрет самостоятельного назначения ролей/подразделения/общей аналитики, проверка Origin и замена предыдущей сессии при регистрации. Для прежних API-клиентов сохранён вход по email. Основные интеграционные сценарии и smoke переведены на ники.

Результат команд: `typecheck`, `lint`, production `build` — успешно; модульные тесты — 17/17; интеграционные — 31/31. В основной базе пять миграций применены. После перезапуска локального dev-сервера для обновления экземпляра Prisma выполнен успешный `smoke`: 12 страниц доступны, база подключена, вход/выход по никам employee/manager/admin/owner и полномочия четырёх кабинетов подтверждены. В основном реестре осталось 20 исходных синтетических обращений. Сервер оставлен работающим на http://localhost:3000.

Браузерная проверка кликов не выполнена: Computer Use сообщил `The browser access host is unavailable`; при обращении к окну Chrome — `window is minimized`. Регистрация и повторный вход подтверждены через API, визуальная отрисовка форм этим прогоном не подтверждена.

### Упрощение ника

В нике разрешены пробелы и начало с точки, дефиса или подчёркивания. Например, `yu _otsaka3301` принимается. Повторяющиеся пробелы нормализуются одинаково при регистрации и входе; размер букв по-прежнему не важен. Длинное сообщение о формате заменено короткой ошибкой под полем, которая очищается при вводе. Для занятого ника также показывается короткая подсказка под полем.

Повторно прошли TypeScript, ESLint, 17 модульных и 31 интеграционный тест. Существующий сквозной сценарий проверяет ник с пробелом и подчёркиванием после него, повторный вход с несколькими пробелами и заглавными буквами, сохранность аккаунта и обращения. Конкурентная регистрация проверяет коллизию ников, начинающихся с подчёркивания, при разном числе пробелов. Изменение схемы БД не требуется.
