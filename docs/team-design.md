# Сотрудники: оформление и проверка

`/team` подключён к существующему HomeShell. Для ADMIN и MANAGER активен пункт сотрудников/команды; EMPLOYEE по прямому адресу получает собственную запись без административного меню. Новые стили `team.css` ограничены `.workspace-team`: Sidebar #0A1427, белые/тёмные поверхности по теме, красные основные действия, компактная таблица, скругления, читаемые подписи. Общий `AdminDirectory` сохраняет прежние ветки справочников; для них не добавлен новый контейнер или новые стили.

Список пользователей и пагинация по 20 записей сохранены. Поиск и фильтры не добавлялись. Для администратора активность учётной записи и доступ к общей аналитике разделены. Для роли ADMIN отмечен доступ по роли, для остальных — дополнительное разрешение. Вместо неработающей кнопки изменения своей записи администратор видит текст «Ваша запись»; клиентский обработчик также не открывает такое редактирование.

Пустые состояния различаются для администратора, руководителя и сотрудника. Неизвестное имя подразделения не подменяется вымышленным названием. При неполной странице справочника видны число загруженных записей и общее число; в редакторе также указан лимит. Новых запросов полного справочника или новых фильтров нет.

Повтор на странице обновляет пользователей и подразделения; в диалоге можно отдельно повторить получение подразделений. Сохранение блокируется при их загрузке/ошибке, создание — при отсутствии активных подразделений. Если текущее подразделение редактируемого пользователя недоступно в загруженном списке или отключено, оно показано отдельным текущим вариантом. Неизменённый departmentId не отправляется в PATCH: это сохраняет текущую привязку и не вызывает ложную ошибку проверки активного подразделения. Осознанная смена отправляется как прежде.

Диалог сохраняет введённые значения при ошибке, показывает общую ошибку и сообщения возле известных полей API, связывает их через aria-describedby/aria-invalid и фокусирует первое ошибочное поле. Пароль остаётся необязательным при редактировании. Сохранены роли, дополнительное право аналитики, активность и предупреждение о завершении сессий после изменения. Параллельная повторная отправка блокируется. Серверные запреты и API не изменены.

На мобильных таблица прокручивается горизонтально, длинные имена/почта/подразделения переносятся. Форма становится одноколоночной, поля имеют размер текста 16 px. Dialog сохраняет нативное поведение модальности и естественную прокрутку. Новая логика не меняет остальные административные страницы.

Проверки: typecheck, lint, 427 тестов и build прошли. DOM-тесты в обеих темах проверяют роли, отсутствие административных действий у EMPLOYEE/MANAGER, собственную запись администратора, список, пагинацию, создание/редактирование, дополнительное право, активность, недоступные подразделения, неполный справочник, загрузку/ошибки/повтор, сохранение ввода и отмену диалога. API в UI-тестах подменён, реальные пользователи не создавались и не изменялись.

Отдельные тесты вызывают существующий usersGet с подменённой БД и проверяют реальные условия запроса: EMPLOYEE — собственный id, MANAGER — активные пользователи своего подразделения, ADMIN — все. Право общей аналитики не расширяет usersGet. Существующие createUser/updateUser проверены на отказ EMPLOYEE/MANAGER и отказ ADMIN при self-edit до обращения к БД. Схема регистрации отвергает внедрение role/canViewCompanyAnalytics.

Существующие тесты ранее обновлённых страниц прошли. Backend, API, авторизация, PostgreSQL, модель пользователей и миграции не изменялись. Dashboard и его стили не изменены. Build завершился с прежним предупреждением о внешнем lock-файле в D:\Projects.

HTTP-проверки: `/`, `/team`, `/settings/categories` возвращают 200; `/api/v1/health` — 200, database connected. Это не подтверждает реальный вход и загрузку списка под тремя аккаунтами. Браузерный сервис недоступен (`The browser access host is unavailable`): скриншот, визуальная мобильная проверка, реальная Tab-навигация, фокус-ловушка и возврат фокуса диалога остаются открытыми. Push и deployment не выполнялись.
